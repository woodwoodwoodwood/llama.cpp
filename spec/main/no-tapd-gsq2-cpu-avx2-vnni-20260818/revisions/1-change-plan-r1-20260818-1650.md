# Change plan：GSQ2 CPU AVX2/AVX_VNNI 点积核

代码已在 `gsq2-quant-type` / `9faf2bdd7`。`/ai-go` 按本图核对 diff，不重写核、不扩 scope。

### A. 问题分析与方案总述【必填】
- 问题分析：`type_traits_cpu[GGML_TYPE_GSQ2].vec_dot` 指向 `ggml_vec_dot_gsq2_q8_0`（`ggml/src/ggml-cpu/ggml-cpu.c:235`）。改核前 x86 的 `arch-fallback.h` 把 `ggml_vec_dot_gsq2_q8_0_generic` alias 成同一符号，于是 `arch/x86/quants.c` 没有独立实现，运行的是 `ggml/src/ggml-cpu/quants.c:180` 的标量循环（每字节拆 4 个 2-bit，再 `code-2` 乘 Q8）。同文件里 Q4/IQ2 等已有 AVX2 + `mul_sum_i8_pairs_float`。`-cmoe` 时专家权重走这条 CPU `vec_dot`，标量核把 decode 卡在约 16 t/s。CUDA 已有 `vec_dot_gsq2_q8_1`（`ggml-cuda/vecdotq.cuh`），不在本次范围。
- 方案总体思路：按现有 x86 低比特核的模式补 `ggml_vec_dot_gsq2_q8_0`：AVX2 unpack 32 个 2-bit → byte，减 2，再复用 `mul_sum_i8_pairs_float`（有 `__AVXVNNI__` 走 `vpdpbusd`，否则 maddubs）。同时去掉 **仅 x86** 分支上的 generic alias，让 `quants.c` 的 generic 与 `arch/x86/quants.c` 的优化核成为两个符号。不新写 codebook，不改 `block_gsq2`。选这条而不是手写另一套累加，是为了和 Q4_0/IQ 路径同一套 VNNI/maddubs 语义，降低数值分叉。

### B. 代码定位【必填】
- `ggml/src/ggml-cpu/arch/x86/quants.c` — 增加 `bytes_from_2bit_32`（约 L98–113）与 `ggml_vec_dot_gsq2_q8_0`（约 L720–761）。签名：`void ggml_vec_dot_gsq2_q8_0(int n, float *s, size_t bs, const void *vx, size_t bx, const void *vy, size_t by, int nrc)`。`#if defined(__AVX2__)`：每个 GSQ2 block（`QK_GSQ2=128`）拆 4 次、每次 32 元，对应 4 个 `block_q8_0`；`#else` 调 `ggml_vec_dot_gsq2_q8_0_generic`。
- `ggml/src/ggml-cpu/arch-fallback.h` — 仅在 `#elif defined(__x86_64__) || defined(__i386__) || defined(_M_IX86) || defined(_M_X64)`（约 L85–111）**删除** `#define ggml_vec_dot_gsq2_q8_0_generic ggml_vec_dot_gsq2_q8_0`。generic / ARM / POWERPC / 其它分支的 alias **保留**。
- 不改：`ggml-common.h` 的 `block_gsq2`、`quantize_row_gsq2_ref` / `dequantize_row_gsq2`、`ggml-cpu.c` 的 type traits 注册、CUDA `vec_dot_gsq2_*`、`testing/CMakeLists.txt`（本地编过 CUDA 的修复，不进本 MR）。

### C. 调用链影响【必填】
- `ggml_vec_dot_gsq2_q8_0` — 调用方：`ggml/src/ggml-cpu/ggml-cpu.c:235` `type_traits_cpu[GGML_TYPE_GSQ2].vec_dot`。上层 `ggml_mul_mat` / CPU backend 经 type traits 间接调用，无第二处直接点名。
- `ggml_vec_dot_gsq2_q8_0_generic` — 声明 `ggml/src/ggml-cpu/quants.h:76`；定义 `ggml/src/ggml-cpu/quants.c:180`。x86 AVX2 核的 `#else` 与非 x86 fallback alias 仍用它。公开签名不变，调用方不用改。
- `bytes_from_2bit_32` — 仅被本文件 `ggml_vec_dot_gsq2_q8_0` 使用，无外部调用方。

### E. 测试要点【必填】
- [unit / compile] 以 `GGML_CUDA=ON` + `GGML_CPU_ALL_VARIANTS=ON` 编出 `llama-server`，x86 变体（至少 haswell/alderlake）成功链接 `ggml_vec_dot_gsq2_q8_0`。通过：链接无 undefined reference。
- [unit / 静态] `arch-fallback.h` 的 x86 `#elif` 内不存在 `ggml_vec_dot_gsq2_q8_0_generic`→`ggml_vec_dot_gsq2_q8_0` 的 `#define`；generic 与 ARM 等分支仍有该 alias。通过：对文件检索即可二元判断。
- [unit / 缺口] 仓库**没有** GSQ2×Q8 CPU `vec_dot` 对照单测。本轮不伪称单测已覆盖；若后续补测，最小集是：随机 `block_gsq2` + `block_q8_0[4]`，AVX2 核与 `ggml_vec_dot_gsq2_q8_0_generic` 的 float 结果在合理 ulp 内一致。
- [integration / 人工] `marvis-local-bench`：`gsq2-*-mtp-q4k.gguf`，`-cmoe -ub 1024`，`context_75k`。通过：decode 明显高于标量基线 ~16 t/s，进入约 28–31 t/s（同机 Q5_K_M 带宽档）；TTFT 不因本核明显变差（prefill 仍主要在 GPU + 大批量 CPU MoE）。
- [integration / 回归] 生成文本相对改核前无乱码/明显语义崩（抽检一轮 500 token）。通过：能正常结束且可读。

### G. 风险待办【必填，可为空】
- bit 序或 `code-2` 与 `quantize_row_gsq2_ref` / generic 不一致 → 全图 decode 静默错。触发：unpack 未按 LSB-first。影响：所有 GSQ2 CPU MoE。缓解：unpack 注释与 generic L210–215 对齐；有单测前靠端到端抽检。
- 无 GSQ2 CPU 单测 → CI 不能锁数值。影响：后续改 `mul_sum_i8_pairs_float` 可能连带破坏 GSQ2。待办：verify 报告必须写明「unit 未跑 GSQ2 vec_dot」。
- 本机 `testing/CMakeLists.txt` 的 CUDA `enable_language` 补丁不在本次 diff。误提交会把无关构建修复带进 MR。
