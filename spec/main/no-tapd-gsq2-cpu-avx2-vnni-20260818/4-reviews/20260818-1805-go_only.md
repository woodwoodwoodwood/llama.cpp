## C. P1 应改项
- `tests/test-quantize-fns.cpp:162` / `:182` — 给 GSQ2 套了 2-bit / lowbit 阈值，但 `GGML_BACKEND_DL=OFF` 下该 target 仍会红。
  - 证据：独立 AVX2 + `GGML_BACKEND_DL=OFF` 构建跑 `test-quantize-fns`：`absolute quantization error=0.007958`（限 0.0075），`dot product error=0.213206`（限 0.04）。根因在 `quantize_row_gsq2_ref` 的 `d=amax/2` 与非对称 codebook `{-2,-1,0,1}`：正侧只覆盖到 `+d=+amax/2`，测试数据 `0.1+2*cos` 的极值在正侧，大量正峰被夹到 `+1`。这不是 AVX2 核的错。
  - 建议：**不要改量化公式**（§B 明确不改 quantize）。要么在 `test_vec_dot_q` 对 `GGML_TYPE_GSQ2` `continue` 并注释原因，要么给 GSQ2 单独放宽到能过的阈值。plan 已声明本机 DL 构建不编此 target，所以不升 P0；但改了阈值却仍失败，非 DL CI 会红。

## D. P2 建议项
- `tests/test-gsq2-vec-dot.cpp:202` — 对照用 `Q8_0.from_float_ref`，`mul_mat` 内部用 CPU `from_float`（x86 为 round-to-even 向量量化）。单元素差 1 LSB 时点积可偏约 `2*d0*d1`，远超 `1e-4`。本机已绿，但不能保证所有数据/实现都绿。建议对照也走 CPU `from_float`，或把容差放到一档 Q8 量化步长。
- `tests/test-gsq2-vec-dot.cpp:118` — 只比「当前 CPU backend」和本地 generic。非 AVX2 变体（x64/sse42/sandybridge 等）走 `#else`，测试变成 generic vs generic，假绿。建议日志打印 backend description，无 AVX2 时 skip-with-notice。
- `ggml/src/ggml-cpu/arch/x86/quants.c:102` — `_mm_loadl_epi64(&qs[k*8])`：`qs` 在 `block_gsq2` 里 offset=2，指针 2-byte 对齐。现代 x86 的 `movq` 能跑；同文件其它 helper 用 `memcpy` / `_mm_loadu_*`。可改成 `memcpy` + `_mm_cvtsi64_si128`，避免 alignment sanitizer。
